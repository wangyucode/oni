目标：增加一个新的 tab「其它工具」，包含 3 个计算器：
- 制氧用水需求
- 食物需求
- 火箭计算

约束：
- 先完成可用版本，不做过度抽象
- 不改后端协议，优先前端静态配置 + 计算规则
- 保持与现有项目交互风格一致（NutUI + Taro）

---

一、总任务拆分（按里程碑）

M1：信息架构与入口搭建（仅页面骨架）
1. 路由与 tab 入口
   1) 在 app 配置中新增 pages/other-tools/other-tools 页面
   2) tabBar 新增“其它工具”入口，调整 tab 顺序与图标资源
   3) 确认小程序与 H5 两端均可进入
2. 页面结构
   1) 新建其它工具首页，展示 3 张工具卡片
   2) 每张卡片跳转到对应子页面（制氧/食物/火箭）
   3) 统一返回逻辑（H5 显示返回按钮，小程序走导航栈）
3. 状态管理策略
   1) 先采用页面内局部状态，避免提前引入复杂全局 store
   2) 每个工具单独维护输入、结果、校验状态
   3) 预留“保存上次输入”的本地缓存键名规范

M2：制氧需求计算器（第一优先级）
1. 数据来源
   1) 复制人耗氧100g/s
   2) 制氧建筑列表，从DataContext中 建筑>氧气 中获取
2. 交互流程（按用户操作路径）
   1) 选择复制人数量
   2) 选择制氧方式（单选）
   3) 自动展示该方式的直接材料需求
   4) 点击某材料，选择来源：
      - 外部输入：直接计入最终结果
      - 建筑生产：进入下一层需求展开
   5) 自动递归展开并配平下游材料
   6) 输出“最终外部输入清单”
3. 计算逻辑拆分
   1) 需求目标换算：复制人数 -> 总耗氧 -> 目标产氧
   2) 主方式换算：目标产氧 -> 主设备规模 -> 直接材料
   3) 来源展开：建筑输出能力 -> 所需建筑数量 -> 上游材料
   4) 配平规则：按“满足需求最小值”向上取整或保留小数（需统一）
   5) 去环处理：检测循环依赖，禁止无限递归
4. 结果展示
   2) 明细表：按材料显示“总需求、内部供给、外部缺口”
   3) 链路视图：显示材料来源路径，支持折叠
5. 异常与边界
   1) 输入 0 人时结果清零
   2) 方式参数缺失时给出提示，不参与计算
   3) 建筑来源无法覆盖时回退为外部输入并标注

M3：食物需求计算器（第二优先级）
1. 数据建模
   1) 复制人日卡路里需求，可以参考产物计算的“饥饿/功率难度”
   2) 食物配方，可以从食物建筑中的电烤炉,油炸锅，敲蛋桌，燃气灶，食物压制器，熏炉获取
   3) 动植物周期产量（每周期、每只、每株）可在小动物，植物种获取
2. 交互流程
   1) 选择复制人数量，及难度选择
   2) 选择目标食物（可选多个 + 占比）
   3) 自动计算目标总卡路里
   4) 展开生产链，换算到“需要多少只动物/多少株植物”
   5) 输出最低养殖/种植规模
3. 计算逻辑拆分
   1) 卡路里目标换算：人口 -> 周期总需求
   2) 食谱换算：成品需求 -> 各级材料需求
   3) 产能换算：材料需求 -> 动物/植物数量
   4) 舍入策略：默认向上取整，支持显示理论值
4. 结果展示
   1) 总览：满足人口所需的总食物规模
   2) 养殖建议：按动物/植物分组输出数量
   3) 配方缺口：缺失原料与补充建议
5. 边界与规则
   2) 占比和不为 100% 时自动归一化或提示修正

M4：火箭计算器（第三优先级）
1. 数据建模
   1) 引擎参数：基础推力、燃料类型、效率
   2) 仓体参数：每个仓体增加的质量/阻力/航程影响
   3) 燃料参数：不同燃料的有效航程贡献
2. 交互流程
   1) 选择引擎
   2) 输入飞行距离
   3) 选择各类仓体数量
   4) 输出最小可行燃料配置
3. 计算逻辑拆分
   1) 根据仓体数量计算总负载
   2) 根据目标距离反推最低燃料量
   3) 若多燃料方案可选，按“燃料最少优先”排序
4. 结果展示
   1) 推荐方案（最省燃料）
   2) 备选方案（不同燃料组合）
   3) 不可达提示（当前配置无法覆盖距离）
5. 对标校验
   1) 抽样对比参考站点结果
   2) 记录偏差原因（参数口径差异）

二、跨工具公共任务

1. 公共输入组件
   1) 人口输入（Stepper）
   2) 距离输入（数字输入 + 单位）
   3) 来源选择弹窗（单选）
2. 公共计算能力
   1) 单位换算（秒/周期、g/kg、kcal）
   2) 数值格式化（保留位数、千分位）
   3) 舍入与误差策略统一
3. 公共展示组件
   1) 结果总览卡
   2) 资源明细网格/列表
   3) 依赖链展开面板
4. 本地缓存
   1) 每个工具独立缓存 key
   2) 进入页面自动恢复上次输入
   3) 提供“清空当前工具输入”按钮

---

四、每个工具的完成定义（DoD）

制氧工具 DoD
1. 可输入人口并得到净水外部需求
2. 可为材料选择来源并触发链路配平
3. 结果区能区分“内部供给/外部缺口”

食物工具 DoD
1. 可输入人口并选择食物
2. 可展开到动物/植物养殖规模
3. 结果可读且可复算

火箭工具 DoD
1. 可输入引擎、距离、仓体数量
2. 可输出最小可行燃料配置
3. 不可达时有明确提示

五、风险与前置决策

1. 风险：游戏版本差异导致参数口径不一致
   - 处理：参数集中管理，页面显示“参数版本”
2. 风险：链路递归出现循环依赖
   - 处理：引入 visited 集合并给出中断提示
3. 风险：食谱数据不全导致断链
   - 处理：断链节点标红并显示需人工补充
4. 风险：火箭公式口径与参考站点不一致
   - 处理：保留“参考模式/本地模式”对比字段
